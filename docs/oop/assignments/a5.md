**Part I: what "type" of function is it?** A **friend function**: an ordinary non-member function that the class names with `friend`, which lets it read private members. It has no `this`, so it receives the objects as parameters. Distance = √((6 − 2)² + (6 − 3)²) = √25 = 5.

**Part II: a member of another class as a friend.** Only `calculate::midPoint` is given access, not the whole `calculate` class. This needs a careful order:
1. `class Point;` (forward declaration) so `calculate` can mention `Point`.
2. `class calculate` with `midPoint` **declared** but not defined, because `Point` is still incomplete: its members are unknown.
3. `class Point` with `friend Point calculate::midPoint(...)`.
4. The **definition** of `calculate::midPoint` **after** `Point` is complete.

**Part III: a whole class as a friend.** `friend class calculate1;` inside `Point` opens all of `Point`'s privates to every member of `calculate1`.

::: warning Two mistakes in the question itself
- "Make **point class a friend of** calculate1" is backwards. That would let `Point` see `calculate1`'s privates. The functions need to read `Point`'s data, so **`calculate1` must be a friend of `Point`**: `friend class calculate1;` goes inside `Point`. Say this in one line.
- "2DCrossProduc Magnitude" is not a legal name: identifiers cannot start with a digit or contain spaces. The program uses `crossProduct2DMagnitude`.
:::

::: danger Friendship facts examiners like
Friendship is **granted** by the class being opened, is **not mutual** (Point friending calculate1 gives Point nothing) and is **not inherited**.
:::

<Q id="A5.Q6">

Write a C++ program to implement an Employee Salary Management System using a class Employee (empID, name, monthlySalary): a static count initialised outside the class and incremented per object; static companyName and retirementAge initialised inside the class; a static constexpr MAX_SALARY; member functions calculateAnnualSalary(), calculateRetirementYears(int currentAge) and calculateSalaryPercentage(); static member functions calculateAverageSalary() and displayCompanyDetails(); at least three employees; and comments explaining why count is initialised outside while the others can be initialised inside, and the difference between inline static and static constexpr.

::::: details Solution

::: code-group

<<< @/../code/oop/assignments/a5-q6.out{txt} [Output]
:::

**The four kinds of member in one class.**

| Member | Kind | Copies | Can change? | Where initialised |
|---|---|---|---|---|
| `empID`, `name`, `monthlySalary` | ordinary | one per object | yes | constructor |
| `count` | `static` | one for the class | yes | **outside**: `int Employee::count = 0;` |
| `companyName`, `retirementAge` | `inline static` | one for the class | yes | inside the class (C++17) |
| `MAX_SALARY` | `static constexpr` | one for the class | **no** | inside, must be a compile-time constant |

**Why `count` goes outside (part k).** A class body is a blueprint: `static int count;` there only *announces* the variable. Storage must be created exactly once in the whole program, by the definition outside. `inline` (C++17) changes the rule: it tells the linker duplicates are fine and to keep one, so the definition can live inside the class. `constexpr` static members are implicitly `inline`, so they go inside too.

**inline static vs static constexpr.** Both are shared by all objects. `inline static` can be changed at run time (the program changes `retirementAge` to 62 and every employee sees it). `static constexpr` is fixed when the program is compiled; assigning to it does not compile.

**Static member functions** (`calculateAverageSalary`, `displayCompanyDetails`) have no `this`, so they use only static members; that is why the average is computed from a static `totalSalary`, not from any one employee's salary.

**Which function runs (parts e, f, g).**

| Line | Runs | Why |
|---|---|---|
| `Student s2 = s1;` | copy constructor | new object; the `=` is initialisation syntax |
| `Student s3(s1);` | copy constructor | new object, direct initialisation |

**Deep copy (parts d, h, k).** Each copy gets its **own** new blocks and copies the characters and numbers into them. Changing `s2`'s mark or `s4`'s name leaves `s1` untouched, as the output shows. `operator=` must also free the blocks `s4` already had (else a leak), and check `this == &s` first (else `s4 = s4` would free its own data before copying it).

| Hybrid | every `Student` here | ordinary members in the object; `name`, `marks` on the heap | object automatically, heap parts by the destructor |
