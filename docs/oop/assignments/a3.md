<Q id="A3.Q6">

Write a C++ program to dynamically allocate an integer array and increase its size from n to 2n when the user wants to insert additional elements. Copy the old elements into the new array and release the old memory.

::::: details Solution

::: code-group
<<< @/../code/oop/assignments/a3-q6.cpp [Program]
<<< @/../code/oop/assignments/a3-q6.in{txt} [Input]
<<< @/../code/oop/assignments/a3-q6.out{txt} [Output]
:::

A heap block cannot grow in place, so "growing" is four steps: **allocate** a block twice the size, **copy** the old elements across, **`delete[]`** the old block, **point** the old pointer at the new block. Capacity goes 3 → 6 → 12 as nine numbers arrive. (This is exactly what `std::vector` does for you.)

::: danger
Forgetting `delete[] arr` before `arr = bigger` leaks the old block; deleting `bigger` instead leaves `arr` dangling.
:::

</Q>

<Q id="A3.Q8">

Write a C++ program to dynamically allocate an integer array of n elements using new, read and display it, compute the sum and maximum, and then demonstrate a situation where the memory is not released. Identify the resulting memory leak and fix it with delete[]. Also see why delete[] must be used instead of delete for a dynamically allocated array.

::::: details Solution

::: code-group
<<< @/../code/oop/assignments/a3-q8.cpp [Program]
<<< @/../code/oop/assignments/a3-q8.out{txt} [Output]
:::

**The leak.** In `sumLeaky`, `arr` is a local pointer. When the function returns, the pointer is destroyed, but the heap block it pointed at is not. Nothing refers to that block any more, so it can never be freed. Leaks do not change the output; they slowly eat memory in long-running programs.

**The fix** is one line, `delete[] arr;`, before the pointer goes out of scope.

**Why `delete[]` and not `delete`.** Memory from `new[]` must be released with `delete[]`, and memory from `new` with `delete`. `delete[]` knows it is releasing an array and, for arrays of objects, runs the destructor of **every** element. Mixing them is undefined behaviour.

</Q>

::::: details Solution

::: code-group
<<< @/../code/oop/assignments/a3-q12.cpp [Program]
<<< @/../code/oop/assignments/a3-q12.out{txt} [Output]
:::

- **By value: not effective.** The function swaps its own copies; `x` and `y` never change.
- **By reference: effective.** `a` and `b` *are* `x` and `y`.
