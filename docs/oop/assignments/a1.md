Write a program that accepts two integers and perform division of these integers and display result in floating point number. Use appropriate type conversion for this and understand the concept of type casting.

::::: details Solution

::: code-group

<<< @/../code/oop/assignments/a1-q5.in{txt} [Input]
<<< @/../code/oop/assignments/a1-q5.out{txt} [Output]
:::

- **Implicit conversion** (automatic, "type promotion"): in `a / (b * 1.0)`, one operand is a `double`, so the other is converted and the division is done in `double`.
- **Explicit conversion** (a cast, written by you): `(float)a` (C style) or `static_cast<double>(a)` (C++ style).
- **The trap, `(double)(a / b)`:** the brackets make the integer division happen first (7 / 2 = 3); converting 3 afterwards gives 3.0. Cast an **operand**, not the result.

With a = 2, b = 3, c = 4, d = 10, e = 5, f = 5, g = 1, h = 2:
`(2 + 12) > 10` is true; `5 != 5` is false, `1 <= 2` is true, so the `||` is true; true `&&` true = **1**.

| Operator(s) | Precedence (high to low) | Associativity |
|---|---|---|
| `( )` | 1 | left to right |
| `*` | 2 | left to right |
| `+` | 3 | left to right |
| `>` `<=` | 4 | left to right |
| `!=` | 5 | left to right |
| `&&` | 6 | left to right |
| `\|\|` | 7 | left to right |
| `=` | 8 (lowest here) | **right to left** |

`&&` and `||` also **short-circuit**: if the left side of `&&` is false, the right side is not evaluated at all.

Write a program to demonstrate the use of the comma operator. The program should initialize a variable using comma expressions, for example `x = (10, 20, 30);`, and understand the logic behind the value stored in x.

::::: details Solution

::: code-group
<<< @/../code/oop/assignments/a1-q8.cpp [Program]
<<< @/../code/oop/assignments/a1-q8.out{txt} [Output]

- `x = (10, 20, 30);` → **30**. Inside brackets, the comma operator evaluates left to right and the result is the **last** value.
- `y = 10, 20, 30;` → **10**. No brackets: `=` has higher precedence than `,`, so this is `(y = 10), 20, 30;`.
- `(i++, i++, i * 100)` → the comma is a **sequence point**: each part finishes before the next starts, so this is well defined: i = 2, z = 200.

**Output: `1526`**, which is `a` = 15 followed immediately by `x` = 26 (no space is printed between them).

- `a = (b = 5, c = 10, b + c)` → b = 5, c = 10, value 15 → **a = 15**.
- `x = (x += 5, x *= 2, x -= 4)` → 10 + 5 = 15 → 15 × 2 = 30 → 30 − 4 = 26 → **x = 26**.

::: info A compiler warning you may see here
GCC warns `operation on 'x' may be undefined`. It is a false alarm: the commas are sequence points, and the outer `=` stores only after the whole bracket is evaluated, so the result is well defined. (Compare `x = x++ + ++x`, which really is undefined.)
:::

::: danger Missing-space trap
The output is `1526`, not `15 26`. When `cout` prints two numbers with nothing between them, they run together. Quizzes use this.
:::

</Q>

Work in binary: a = 6 = `110`, b = 3 = `011`.

| Expression | Binary | Decimal | Rule |
|---|---|---|---|
| `a & b` | `010` | 2 | 1 where both are 1 |
| `a \| b` | `111` | 7 | 1 where either is 1 |
| `a ^ b` | `101` | 5 | 1 where they differ |
| `~a` | all bits flipped | −7 | `~n` is always `−(n + 1)` |
| `a << 1` | `1100` | 12 | shift left = × 2 |
| `a >> 1` | `011` | 3 | shift right = ÷ 2 (drops the remainder) |

**Three different `x`s are in play.** Keep them apart and the trace is mechanical.
- `::x`, the **global**, starts at 10.
- `main`'s **local** `x` starts at 3 and only `main` changes it.
