<Q id="S25.Q1a" title="Feature scaling">

When do we prefer min-max scaling over standardization? Justify with an example.

::::: details Solution

**Min-max scaling** maps a feature onto [0, 1]: $x' = \dfrac{x - \min}{\max - \min}$. **Standardization** (z-score) centres it and divides by the spread: $z = \dfrac{x - \mu}{\sigma}$, giving mean 0 and standard deviation 1 with no fixed range.

**Prefer min-max when:**
1. **The model needs inputs in a fixed range, or assumes no distribution.** KNN and neural networks are the slide's examples. Distances and activations behave best when every feature lives in the same bounded range.
2. **The data is not Gaussian** (skewed, uniform, or unknown shape). Standardization is built around mean and standard deviation, which describe a bell curve well and other shapes badly.
3. **The feature has hard natural limits.** Pixel intensities run 0 to 255, percentages 0 to 100, ratings 1 to 5. Min-max keeps that meaning: 0 stays "none" and 1 stays "maximum".

**Example.** A grey-scale image has pixel values from 0 to 255. Min-max gives $x' = x/255$, so a pixel of 51 becomes 0.2 and a pixel of 255 becomes 1. Every pixel is in [0, 1], the order is kept, and a neural network's inputs are all on one scale.

**When not to.** One outlier ruins min-max. If one salary is 50 times the rest, it becomes the max, and every other salary is squeezed close to 0. Standardization is less sensitive (the outlier only widens σ) and also copes when min and max are unknown, so use it for roughly Gaussian data or data with outliers.

::: danger Where marks go
- Give a **reason** for each case, not a list of algorithm names.
- The example must show the arithmetic (51 → 0.2), not just say "images".
- Do not write "standardization scales to 0–1". One slide says so, and the slide after it contradicts it. Standardization has no bounded range. See [the correction in Unit 2](../notes/unit-2#scaling).
:::

<Q id="S25.Q1b" title="One-hot encoding">

Assess any two potential issues of applying one-hot encoding to a dataset with high cardinality w.r.t. categorical features.

::::: details Solution

High cardinality means a categorical feature has many distinct values, for example a PIN-code column with 3,000 values. One-hot encoding creates **one new 0/1 column per value**. Any two of these issues, each with its reason:

1. **Dimensionality explosion (curse of dimensionality).** 3,000 values become 3,000 columns. The model needs far more data to learn a weight for each, and distance-based models such as KNN degrade because points become almost equidistant in high dimensions.
2. **Sparse, memory-hungry data.** Every row has a single 1 and 2,999 zeros. The matrix is mostly zeros, so it wastes memory and slows training.
3. **Overfitting on rare categories.** Many values appear only a handful of times. The model learns a separate weight for each from very few rows, which fits noise.
4. **Multicollinearity (the dummy-variable trap).** The N columns always add up to 1, so any one is exactly predictable from the rest. Linear and logistic regression cannot separate their effects. Dummy encoding (N − 1 columns) is the slides' fix.
5. **Unseen categories at test time.** A value that never appeared in training has no column, so the encoder must ignore it or fail.

**Remedy (adds a mark):** group rare values into "Other", or **generalise** up the concept hierarchy before encoding (PIN code → city → state), or use frequency or target encoding, which keeps a single column.

::: tip Answer shape for "assess two issues"
Name the issue in bold, explain the mechanism in one sentence, and quantify it with the example (3,000 columns). Two issues done this way beat five listed without reasons.
:::

<Q id="S25.Q3" title="ROC curve and AUC">

A binary classifier is tested on 6 samples. The true labels and predicted probabilities of the positive class are:

| Sample | True label | Predicted probability (positive class) |
|:-:|:-:|:-:|
| S1 | 1 | 0.9 |
| S2 | 0 | 0.8 |
| S3 | 1 | 0.7 |
| S4 | 0 | 0.6 |
| S5 | 1 | 0.4 |
| S6 | 0 | 0.3 |

(a) Construct the ROC curve table by setting thresholds at {0.9, 0.8, 0.7, 0.6, 0.4, 0.3}. (b) Calculate the TPR and FPR for each threshold. (c) Interpret the ROC and estimate the approximate AUC.

::::: details Solution

<!--@include: @/../code/dsml/papers/s25.out#q3-->

**(c) Interpretation.** AUC ≈ **0.67**. The model is better than random guessing (0.5) but weak: on the slides' scale, 0.6–0.7 is graded "poor". The reason is visible in the data: the negative S2 (0.8) outranks two positives, and the positive S5 (0.4) sits below the negative S4. At threshold 0.7 the model catches 2 of 3 positives at a cost of 1 false alarm in 3.

::: danger Where marks go
- One threshold gives **one** confusion matrix, which gives **one** ROC point. Show TP, FP, FN, TN for each, not just the rates.
- TPR divides by the actual **positives** (3), FPR by the actual **negatives** (3).
- Add (0, 0) before you measure the area. Without it the first rectangle is lost and the AUC comes out too small.
:::

<Q id="S25.Q5" title="KNN off a scatter plot">

A KNN classifier assigns a test instance the majority class of its K nearest training instances, with Euclidean distance. The training set of positive (+) and negative (−) instances and a single test instance (o) are plotted on two real-valued features X and Y. Assume unweighted KNN (every nearest neighbour counts equally).

(a) What class is assigned to the test instance for K = 1, K = 3 and K = 5? (b) Setting K to a large value seems like a good idea: we get more votes. Given this training set, would you recommend K = 11? Why or why not?

::::: details Solution

<!--@include: @/../code/dsml/papers/s25.out#q5-->

**(a)** K = 1 → **−**, K = 3 → **−**, K = 5 → **+**. The two − points almost touch the test point; the three + points just below it come next.

**(b) No.** There are only 5 negatives in the whole training set. With K = 11, at least 6 of the 11 votes must be +, wherever the test point is. KNN then ignores the neighbourhood and predicts the majority class everywhere: it has stopped learning (high bias, underfitting). The 2 nearest points, which are the real evidence, are outvoted by points much farther away.

More votes are not better votes: each extra neighbour is farther and less similar. Pick K by **cross-validation** (try K = 1, 3, 5, … and keep the one with the lowest validation error), and keep K odd to avoid ties.

::: tip The rule behind (b)
With two classes, if K is at least twice the size of the smaller class, the smaller class can never win a vote (here 5 negatives, so any K ≥ 10). Say this in one line and you have the marks.
:::
