<Q id="B22.Q1">

Evaluate below postfix expression. Show status of stack and operations at each step:

**10 2 5 3 2 ^ 3 ∗ + 2 ^ ∗ − 10 4 ∗ + 10 −**

::::: details Solution

On an operator: op2 = pop (first), op1 = pop (second), push op1 op op2.

| Token | Operation | Stack (bottom → top) |
|---|---|---|
| 10 | push | 10 |
| 2 | push | 10 2 |
| 5 | push | 10 2 5 |
| 3 | push | 10 2 5 3 |
| 2 | push | 10 2 5 3 2 |
| ^ | op2 = 2, op1 = 3: 3² = 9 | 10 2 5 9 |
| 3 | push | 10 2 5 9 3 |
| ∗ | 9 × 3 = 27 | 10 2 5 27 |
| + | 5 + 27 = 32 | 10 2 32 |
| 2 | push | 10 2 32 2 |
| ^ | 32² = 1024 | 10 2 1024 |
| ∗ | 2 × 1024 = 2048 | 10 2048 |
| − | op2 = 2048, op1 = 10: 10 − 2048 = −2038 | −2038 |
| 10 | push | −2038 10 |
| 4 | push | −2038 10 4 |
| ∗ | 10 × 4 = 40 | −2038 40 |
| + | −2038 + 40 = −1998 | −1998 |
| 10 | push | −1998 10 |
| − | −1998 − 10 = −2008 | −2008 |

**Result: −2008.** The stack is deepest (5 values) right after the first five operands.

::: danger A negative answer is right
At the first `−`, op1 is 10 (pushed first) and op2 is 2048: 10 − 2048. Swapping them gives +2038 and every later value goes wrong. A negative result is a hint you kept the order.
:::

:::::

</Q>

<Q id="B22.Q2">

Priority Queue (PQ) is an abstract data type that is similar to a queue, and every element has some priority value associated with it. The priority of the elements in a priority queue determines the order in which elements are served (i.e., the order in which they are removed). If in any case the elements have same priority, they are served as per their ordering in the queue.

Following operations are performed on a PQ in given order. Operation enqueue(d, p) inserts the element "d" having priority "p" in PQ. Larger priority value implies higher priority. Show the content of PQ after each operation.

enqueue(70, 4), enqueue(90, 2), enqueue(160, 7), enqueue(40, 5), dequeue(), dequeue(), enqueue(20, 1), enqueue(10, 4), enqueue(130, 2), dequeue(), enqueue(40, 6), dequeue(), dequeue(), enqueue(110, 4), dequeue(), dequeue(), enqueue(70, 5), enqueue(5, 6), dequeue(), dequeue()

::::: details Solution

Keep the PQ in serving order: higher priority first, and among equal priorities, earlier arrivals first. Shown as data(priority).

| Operation | Removed | PQ, served first → last |
|---|---|---|
| enqueue(70, 4) | | 70(4) |
| enqueue(90, 2) | | 70(4), 90(2) |
| enqueue(160, 7) | | 160(7), 70(4), 90(2) |
| enqueue(40, 5) | | 160(7), 40(5), 70(4), 90(2) |
| dequeue() | 160 | 40(5), 70(4), 90(2) |
| dequeue() | 40 | 70(4), 90(2) |
| enqueue(20, 1) | | 70(4), 90(2), 20(1) |
| enqueue(10, 4) | | 70(4), 10(4), 90(2), 20(1) |
| enqueue(130, 2) | | 70(4), 10(4), 90(2), 130(2), 20(1) |
| dequeue() | 70 | 10(4), 90(2), 130(2), 20(1) |
| enqueue(40, 6) | | 40(6), 10(4), 90(2), 130(2), 20(1) |
| dequeue() | 40 | 10(4), 90(2), 130(2), 20(1) |
| dequeue() | 10 | 90(2), 130(2), 20(1) |
| enqueue(110, 4) | | 110(4), 90(2), 130(2), 20(1) |
| dequeue() | 110 | 90(2), 130(2), 20(1) |
| dequeue() | 90 | 130(2), 20(1) |
| enqueue(70, 5) | | 70(5), 130(2), 20(1) |
| enqueue(5, 6) | | 5(6), 70(5), 130(2), 20(1) |
| dequeue() | 5 | 70(5), 130(2), 20(1) |
| dequeue() | 70 | **130(2), 20(1)** |

Elements removed, in order: 160, 40, 70, 40, 10, 110, 90, 5, 70. Generated by a checker that applies the same rule.

::: danger The tie rule decides two rows
10(4) arrives after 70(4), so 70 leaves first; 130(2) waits behind 90(2). A new element goes **after** every element of equal priority. That is the same `>=` walk as the sorted-list ENQUEUE in [Oct 2025 Q5](./mst-2025-oct#q5).
:::

:::::

</Q>

<Q id="B22.Q3">

Write a function stretch that takes a nonempty linked list of integers and stretches it so that the first element is replicated one additional time, the second is replicated two additional times, the third is replicated three additional times, and so forth. As an example, the following list:

3 → 4 → 1 → 5 → 1

would be transformed into

3 → 3 → 4 → 4 → 4 → 1 → 1 → 1 → 1 → 5 → 5 → 5 → 5 → 5 → 1 → 1 → 1 → 1 → 1 → 1

The node structure is shown as below:

```python
Class node:
    def __init__(self):
        self.data = None
        self.next = None
```

::::: details Solution

(Written in C++ with the equivalent node class: `data` and `next`.)

Walk the original nodes, keeping their position k. Before inserting copies, **remember the next original node**; insert k copies right after the current node; then jump to the remembered node.

::: code-group
<<< @/../code/ds/papers/b22-q3.cpp#answer [Answer to write]
<<< @/../code/ds/papers/b22-q3.cpp [Full program]
<<< @/../code/ds/papers/b22-q3.out{txt} [Output]
:::

**Complexity:** the list grows from n to n + (1 + 2 + … + n) = n(n + 3)/2 nodes, so O(n²) nodes are created, and the time is O(n²).

::: danger The infinite-loop bug
Moving `t = t->next` after inserting would land on a copy, which then gets copied too, forever. Save `after = t->next` **before** inserting and jump there.
:::

:::::

</Q>

<Q id="B22.Q4">

A new employee at an exciting new software company starts with a salary of $50,000 and is promised that every year, at the start of new year her salary will be double of her previous year's salary, with an extra increment of $10,000.

- i. Construct a recurrence relation for her salary for her nth year of employment. (2)
- ii. Solve this recurrence relation to find her salary for her nth year of employment. Show each step of solution clearly. (3)

::::: details Solution

**(i)** Let Sₙ be the salary in year n.

**S₁ = 50,000;  Sₙ = 2Sₙ₋₁ + 10,000 for n ≥ 2.**

**(ii)** Backward substitution:

```text
Sₙ = 2Sₙ₋₁ + 10000
   = 2[2Sₙ₋₂ + 10000] + 10000   = 2²Sₙ₋₂ + 10000(2 + 1)
   = 2²[2Sₙ₋₃ + 10000] + 10000(2 + 1) = 2³Sₙ₋₃ + 10000(2² + 2 + 1)
after k steps:  2^k Sₙ₋ₖ + 10000(2^(k−1) + ... + 2 + 1) = 2^k Sₙ₋ₖ + 10000(2^k − 1)
base: n − k = 1  ⇒  k = n − 1
Sₙ = 2^(n−1)·50000 + 10000(2^(n−1) − 1)
   = 60000·2^(n−1) − 10000
   = 30000·2ⁿ − 10000
```

**Sₙ = 30,000·2ⁿ − 10,000.** Check: S₁ = 60,000 − 10,000 = 50,000 ✓; S₂ = 120,000 − 10,000 = 110,000 = 2(50,000) + 10,000 ✓; S₃ = 230,000 ✓.

:::::

</Q>

<Q id="B22.Q5">

Why would a Singly Linked List (SLL) be an inappropriate data structure to implement a Double Ended Queue (Deque)? Justify your answer with complexity analysis.

::::: details Solution

A deque needs four operations, and all four should be O(1). With an SLL (head and tail pointers):

| Operation | SLL | Why |
|---|---|---|
| insertFront | O(1) | new node → old head; head = new |
| deleteFront | O(1) | head = head->next |
| insertRear | O(1) | tail->next = new; tail = new |
| **deleteRear** | **O(n)** | the new tail is the node *before* the tail, and an SLL can only find it by walking from the head |

Without a tail pointer, insertRear is O(n) as well. So a sequence of n deleteRear operations costs O(n²) on an SLL.

**Better choices:** a **doubly linked list** (`tail = tail->prev` makes deleteRear O(1)), or a **circular array** with front and rear indices, where all four operations are O(1).

:::::

</Q>
