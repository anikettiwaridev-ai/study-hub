<Q id="P24.Q1">

Find the time complexity in terms of Big-O of the following recurrence relations using substitution (consider log base 2). Show every step:

(i) T(n) = T(√n) + 1  (ii) T(n) = 2T(n/2) + log n

::::: details Solution

**(i) T(n) = T(√n) + 1.** Substitute n = 2ᵐ (so √n = 2^(m/2)) and write S(m) = T(2ᵐ):

```text
S(m) = S(m/2) + 1
     = S(m/4) + 2
     = S(m/8) + 3
after k steps:  S(m/2^k) + k
base: m/2^k = 1  ⇒  k = log₂m
S(m) = S(1) + log₂m
T(n) = S(log₂n) = T(2) + log₂(log₂n)
```

**T(n) = O(log log n).**

Equivalently, without the substitution: T(n) = T(n^(1/2)) + 1 = T(n^(1/4)) + 2 = … = T(n^(1/2ᵏ)) + k; stop when n^(1/2ᵏ) = 2, i.e. (log₂n)/2ᵏ = 1, so k = log₂log₂n.

**(ii) T(n) = 2T(n/2) + log n** (assume T(1) = c, a constant):

```text
T(n) = 2T(n/2) + log n
     = 2[2T(n/4) + log(n/2)] + log n   = 4T(n/4) + 2log(n/2) + log n
     = 8T(n/8) + 4log(n/4) + 2log(n/2) + log n
after k steps:  2^k T(n/2^k) + Σ (i = 0 to k−1) 2^i · log(n/2^i)
                                = 2^k T(n/2^k) + Σ 2^i (log n − i)
base: n/2^k = 1  ⇒  k = log n,  2^k = n

Σ (i = 0 to k−1) 2^i (k − i) = 2^(k+1) − k − 2        (put j = k − i: 2^k Σ j/2^j)
                             = 2n − log n − 2

T(n) = n·c + 2n − log n − 2
```

**T(n) = O(n).**

::: tip Why the log term doesn't matter
The leaves (n of them, each costing c) already cost Θ(n), and the log terms near the top are tiny by comparison. Master-theorem check: n^(log₂2) = n, and log n is polynomially smaller: case 1, Θ(n).
:::

<Q id="P24.Q2">

Write a runnable program that simulates children taking turns to receive candy from a vending machine. Each child can receive up to 5 candies per turn, and if they want more, they must wait for the current queue to complete. The user will input the total number of candies in the machine and a sequence of valid candy requests (up to 100 children). Pass these parameters to a function named candy_crush(), which outputs the number of candies left in the machine after the sequence is completed or the remaining sequence if the candies run out before fulfilling all requests. Use the most suitable data structure to implement this that you studied in your lectures.

::::: details Solution

**Data structure: a queue.** Children are served in arrival order, and a child who still wants candy goes to the **back** ("wait for the current queue to complete"): first in, first out.

Each turn: dequeue a child, give `min(5, still wanted, candies left)`, and if the child still wants more, enqueue them again. Stop when the queue is empty (print the candies left) or the machine is empty (print the remaining requests in queue order).

<Q id="P24.Q4">

Give worst case time complexity for the following. Explain with suitable example.
- a) To reverse a stack (implemented using array) using recursion
- b) To reverse a doubly linked list
- c) To reverse a queue (implemented using array) using another empty queue
- d) Delete the last node in single linked list

::::: details Solution

| Task | Worst case | Why |
|---|---|---|
| a) reverse an array stack with recursion | **O(n²)** | using only push and pop, each of the n elements is inserted at the bottom of a stack of up to n − 1 elements |
| b) reverse a doubly linked list | **O(n)** | one pass swapping each node's `prev` and `next`, then swap head and tail |
| c) reverse an array queue using one empty queue | **O(n²)** | with no stack, each element's turn needs a rotation of the remaining queue |
| d) delete the last node of a singly linked list | **O(n)** | you must reach the second-last node, which only a walk from the head finds |

**a)** Stack 1, 2, 3, 4 (4 on top). `reverseStack` pops 4, reverses 1 2 3, then `insertAtBottom(4)` must pop 3 elements and push them back: insertAtBottom on k elements costs O(k), so the total is 0 + 1 + … + (n − 1) = O(n²). (If the question allowed direct array access, swapping `arr[i]` and `arr[top − i]` recursively would be O(n). As a *stack*, use only push and pop. State the assumption.)

**b)** 1 ⇄ 2 ⇄ 3: visit each node once and swap its two pointers (1's next becomes NULL, 3's prev becomes NULL), then the head becomes 3: 3 ⇄ 2 ⇄ 1. n nodes, constant work each.

**c)** Queue 1 2 3 4 (front 1). To build 4 3 2 1 in the empty queue, its first element must be 4, the current **rear**: dequeue and re-enqueue 3 elements to bring 4 to the front, move it across; then 2 rotations to bring 3 forward, and so on. Moves: (n − 1) + (n − 2) + … = O(n²).

**d)** 10 → 20 → 30 → 40: to delete 40, walk to 30 (n − 2 steps), set `30->next = NULL`, free 40. A tail pointer does not help, because it points to 40, not to 30.

Measured by running (a) and (c) and counting push/pop operations: doubling n roughly quadruples the count, the signature of O(n²).
