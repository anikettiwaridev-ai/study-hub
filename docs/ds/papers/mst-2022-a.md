<Q id="A22.Q1a">

What is the Time Complexity of the following code?

```c
int fun (int n) {
    int i, j;
    for (i=1; i<=n; i++)
        for (j=1; j<n; j+=i)
            printf("%d %d", i, j);
}
```

::::: details Solution

For a fixed i, j runs 1, 1 + i, 1 + 2i, … while j &lt; n: about **n/i** times.

Total = n/1 + n/2 + n/3 + … + n/n = n(1 + 1/2 + … + 1/n) = n · Hₙ ≈ n ln n.

**O(n log n).** (The harmonic series 1 + 1/2 + … + 1/n grows like ln n.) Counted by running: for n = 1000 the inner statement runs 8,045 times; n ln n ≈ 6,908.

::: danger Not O(n²)
Two nested loops do not make n². The inner loop's step grows with i, so it shrinks: n, n/2, n/3, …
:::

:::::

</Q>

<Q id="A22.Q1b">

What is the output of the given Recurrence function if n = 99?

```c
int fun (int n) {
    if (n>100)
        return n-10;
    return fun(fun(n+11));
}
main() { printf("%d", fun(n)); }
```

::::: details Solution

```text
fun(99)  : 99 ≤ 100  → fun(fun(110))
fun(110) : 110 > 100 → 100            so fun(99) = fun(100)
fun(100) : 100 ≤ 100 → fun(fun(111))
fun(111) : 111 > 100 → 101            so fun(100) = fun(101)
fun(101) : 101 > 100 → 91
```

**Output: 91.** This is McCarthy's 91 function: it returns 91 for every n ≤ 100 and n − 10 above 100. Checked by running in [Unit 1](../notes/unit-1#recursion).

:::::

</Q>

<Q id="A22.Q1c">

Evaluate the following postfix expression using a stack: **5 2 7 ^ ∗ 39 13 / − 9 11 ∗ +**

::::: details Solution

| Token | Operation (op2 = first pop) | Stack (bottom → top) |
|---|---|---|
| 5, 2, 7 | push | 5 2 7 |
| ^ | 2 ^ 7 = 128 | 5 128 |
| ∗ | 5 × 128 = 640 | 640 |
| 39, 13 | push | 640 39 13 |
| / | 39 / 13 = 3 | 640 3 |
| − | 640 − 3 = 637 | 637 |
| 9, 11 | push | 637 9 11 |
| ∗ | 9 × 11 = 99 | 637 99 |
| + | 637 + 99 = 736 | 736 |

**Result: 736.**

<Q id="A22.Q2a">

What will be the Time Complexity for the following Recurrence Relation? **T(n) = 8T(√n) + (log n)²**

::::: details Solution

Substitute **n = 2ᵐ**, so √n = 2^(m/2) and log n = m. Let S(m) = T(2ᵐ):

```text
S(m) = 8S(m/2) + m²
     = 8[8S(m/4) + (m/2)²] + m²    = 64S(m/4) + 2m² + m²
     = 512S(m/8) + 4m² + 2m² + m²
after k steps:  8^k S(m/2^k) + m²(1 + 2 + 4 + ... + 2^(k−1))
             =  8^k S(m/2^k) + m²(2^k − 1)
base: m/2^k = 1  ⇒  k = log₂m,  8^k = (2^k)³ = m³
S(m) = m³ S(1) + m²(m − 1) = Θ(m³)
```

Back to n (m = log n): **T(n) = Θ((log n)³)**.

Master-theorem check on S: a = 8, b = 2, m^(log₂8) = m³ dominates f(m) = m²: case 1, Θ(m³).

:::::

</Q>

<Q id="A22.Q2b">

Convert the following Infix notation to Postfix notation: **a + b ∗ (c ^ d − e) ^ (f + g ∗ h) − i**

::::: details Solution

| Symbol | Operation | Stack (bottom → top) | Postfix string |
|---|---|---|---|
| a | output | (empty) | a |
| + | push + | + | a |
| b | output | + | ab |
| ∗ | push ∗ | + ∗ | ab |
| ( | push ( | + ∗ ( | ab |
| c | output | + ∗ ( | abc |
| ^ | push ^ | + ∗ ( ^ | abc |
| d | output | + ∗ ( ^ | abcd |
| − | pop ^, push − | + ∗ ( − | abcd^ |
| e | output | + ∗ ( − | abcd^e |
| ) | pop −, drop ( | + ∗ | abcd^e− |
| ^ | push ^ (higher than ∗) | + ∗ ^ | abcd^e− |
| ( | push ( | + ∗ ^ ( | abcd^e− |
| f | output | + ∗ ^ ( | abcd^e−f |
| + | push + | + ∗ ^ ( + | abcd^e−f |
| g | output | + ∗ ^ ( + | abcd^e−fg |
| ∗ | push ∗ | + ∗ ^ ( + ∗ | abcd^e−fg |
| h | output | + ∗ ^ ( + ∗ | abcd^e−fgh |
| ) | pop ∗ +, drop ( | + ∗ ^ | abcd^e−fgh∗+ |
| − | pop ^ ∗ +, push − | − | abcd^e−fgh∗+^∗+ |
| i | output | − | abcd^e−fgh∗+^∗+i |
| end | pop − | (empty) | abcd^e−fgh∗+^∗+i− |

**Postfix: `abcd^e-fgh*+^*+i-`**

Meaning: a + (b ∗ ((c^d − e) ^ (f + g∗h))) − i. The `^` binds tighter than `∗`, so b multiplies the whole power.

<Q id="A22.Q3">

Build a binary Max-heap of following elements: 12, 13, 25, 14, 10, 8, 16. What is the content of the array after two delete operations on Max-heap? Perform heap sort on it and create a sorted Array (in increasing order). Clearly show all steps and don't include deleted elements to perform heap sort.

::::: details Solution (Unit 8, end-semester only)

**Build by inserting one at a time** (append, then swap upward while larger than the parent):

| Insert | Array after sifting up |
|---|---|
| 12 | 12 |
| 13 | 13 12 |
| 25 | 25 12 13 |
| 14 | 25 14 13 12 |
| 10 | 25 14 13 12 10 |
| 8 | 25 14 13 12 10 8 |
| 16 | 25 14 16 12 10 8 13 |

**Two deletions** (remove the root, move the last element to the root, sift down):

| Delete | Array |
|---|---|
| 25 | 16 14 13 12 10 8 |
| 16 | **14 12 13 8 10** |

**Heap sort** on the remaining 5 (swap the root with the last unsorted cell, shrink, sift down):

| Step | Array (sorted part after the bar) |
|---|---|
| swap 14 ↔ 10, sift | 13 12 10 8 \| 14 |
| swap 13 ↔ 8, sift | 12 8 10 \| 13 14 |
| swap 12 ↔ 10, sift | 10 8 \| 12 13 14 |
| swap 10 ↔ 8 | 8 \| 10 12 13 14 |

Sorted: **8 10 12 13 14**. (Building bottom-up with heapify instead gives 25 14 16 13 10 8 12; either method is accepted if shown.)

<Q id="A22.Q4">

Write a pseudo code to find the smallest element in the Singly Linked List.

::::: details Solution

```text
FIND_SMALLEST(START)
1. if START = NULL then print "List is empty"; return
2. MIN ← START.data            // start from the first node, not from 0
3. P ← START.next
4. while P ≠ NULL do
5.     if P.data < MIN then MIN ← P.data
6.     P ← P.next
7. return MIN
```

<Q id="A22.Q5">

Explain at least 4 differences between malloc() and calloc() function with their respective syntax. What is the purpose of free() function?

::::: details Solution

| | `malloc()` | `calloc()` |
|---|---|---|
| Syntax | `ptr = (int*) malloc(n * sizeof(int));` | `ptr = (int*) calloc(n, sizeof(int));` |
| Arguments | one: the total number of bytes | two: the number of blocks and the size of each |
| Initial contents | garbage (not initialised) | every byte set to **0** |
| Speed | faster (no initialisation) | slightly slower (it zeroes the memory) |
| Typical use | a single object or a buffer you will fill at once | an array that must start at zero |

Both live in `<stdlib.h>`, allocate on the heap, and return `NULL` on failure (and a `void*` that C++ requires you to cast).

**`free(ptr)`** returns heap memory to the system. Without it the memory stays allocated until the program ends (a **memory leak**). After `free`, set `ptr = NULL` so it doesn't dangle.

**In C++** (your course) you use `new` / `delete` (and `new[]` / `delete[]`): they call constructors and destructors and need no cast. The slides say malloc/calloc are "generally not preferred in C++".

:::::

</Q>

What will be the output of the following code snippet for the linked list 1->2->3->4->5->6?

```c
void solve (struct node* start)
{
    if (start == NULL)
        return;
    printf("%d ", start->data);
    if (start->next != NULL )
        solve(start->next->next);
    printf("%d ", start->data);
```

::::: details Solution

| Call | Prints first | Then calls | Prints on the way back |
|---|---|---|---|
| solve(1) | 1 | solve(3) | 1 |
| solve(3) | 3 | solve(5) | 3 |
| solve(5) | 5 | 5→next = 6, so solve(6→next) = solve(NULL) | 5 |
| solve(NULL) | returns | | |

**Output: `1 3 5 5 3 1`**
