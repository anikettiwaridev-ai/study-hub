## Part A · Expressions

### 1. The toolkit: one table for all six conversions {#toolkit}

| Operator | Precedence | Associativity |
|---|---|---|
| `^` | 3 (highest) | **right**: `a^b^c = a^(b^c)`. The only exception |
| `*` `/` | 2 | left: `a/b*c = (a/b)*c` |
| `+` `-` | 1 | left: `a-b-c = (a-b)-c` |

There are only two techniques. **(1) The bracket method** for anything that starts from infix. **(2) A stack of strings** for anything that starts from postfix or prefix. You need the operator-stack algorithm only when a question says "using stack" or "show the stack", which the mid-semester always does.

Operands are always pushed as they are. Below, **a** is the left operand and **b** the right one.

| From → To | Scan | On an operator, pop… | Push back |
|---|---|---|---|
| Postfix → Infix | left → right | **b** first, then a | `(a op b)` |
| Prefix → Infix | right → left | **a** first, then b | `(a op b)` |
| Postfix → Prefix | left → right | **b** first, then a | `op a b` |
| Prefix → Postfix | right → left | **a** first, then b | `a b op` |
| Infix → Postfix | bracket method | move each operator to its **right** bracket | |
| Infix → Prefix | bracket method | move each operator to its **left** bracket | |

::: tip One sentence for the pop order
Postfix is read forwards, so the operand you pop first is the one that came last: the **right** operand. Prefix is read backwards, so the operand you pop first is the one nearest the operator: the **left** operand.
:::

**Three facts that are always true** (use them to check any answer):
1. **Operands never change order.** P Q R S in the infix is P Q R S in the postfix and in the prefix. Only operators move.
2. The operator applied **last** is the **last** symbol of postfix and the **first** symbol of prefix.
3. Operators = operands − 1 (binary operators). Postfix starts with two operands; prefix ends with two operands.

### 2. Infix → Postfix {#infix-postfix}

#### Method 1: the bracket method (fastest by hand)

1. Fully bracket by precedence: `^` first (right to left), then `*` `/` (left to right), then `+` `-` (left to right).
2. Move each operator to just after its matching **closing** bracket.
3. Delete the brackets.

Worked example: `P+Q*(R-S)^T/U`

| Step | Result |
|---|---|
| Bracket `^` first: `(R-S)^T` | `P+Q*((R-S)^T)/U` |
| then `*` and `/`, left to right | `P+((Q*((R-S)^T))/U)` |
| then `+` | `(P+((Q*((R-S)^T))/U))` |
| move operators right, drop brackets | `PQRS-T^*U/+` |

**Faster still, the chunking trick.** Convert the innermost piece, call it a letter, and treat that letter as an operand from then on. X = R−S → `RS-`; Y = X^T → `X T ^`; Z = Q*Y → `Q Y *`; W = Z/U → `Z U /`; P+W → `P W +`. Substitute back: `PQRS-T^*U/+`.

#### Method 2: the stack algorithm (what the mid-semester asks for)

| Symbol | Action |
|---|---|
| operand | write it to the output |
| `(` (or `[`, `{`) | push |
| `)` (or `]`, `}`) | pop to the output until the matching `(`, then discard the `(` |
| operator c | pop while the top is not `(` **and** (top has higher precedence, **or** equal precedence and c is not `^`). Then push c |
| end | pop everything left |

::: tip The pop rule in five words
**Higher or equal pops, except `^`.** Two `^` in a row: the second does NOT pop the first.
:::

Trace of `P+Q*(R-S)^T/U`, generated by running the algorithm. **This is the table to draw in the exam**: the papers say "clearly show the operation performed for each character, the content of stack, and the postfix string after each step".

| Symbol | Action | Stack (bottom → top) | Postfix so far |
|---|---|---|---|
| P | operand → output | (empty) | P |
| + | push + | + | P |
| Q | operand → output | + | PQ |
| * | push * (top + is lower) | + * | PQ |
| ( | push ( | + * ( | PQ |
| R | operand → output | + * ( | PQR |
| - | push − (top is `(`) | + * ( − | PQR |
| S | operand → output | + * ( − | PQRS |
| ) | pop until ( : −, drop ( | + * | PQRS− |
| ^ | push ^ (top * is lower) | + * ^ | PQRS−  |
| T | operand → output | + * ^ | PQRS−T |
| / | pop ^ and * (both ≥ /), push / | + / | PQRS−T^* |
| U | operand → output | + / | PQRS−T^*U |
| end | pop all: / then + | (empty) | **PQRS−T^*U/+** |

### 3. Infix → Prefix {#infix-prefix}

#### Method 1: the bracket method

The same as postfix, but move each operator to its **opening** (left) bracket.

Worked example: `(P-Q/R)*(S+T)-U`

| Step | Result |
|---|---|
| Fully bracket | `(((P-(Q/R))*(S+T))-U)` |
| move operators left, drop brackets | `-*-P/QR+STU` |

Chunking works too: Q/R → `/QR`; P−X → `-P/QR`; S+T → `+ST`; X*Y → `*-P/QR+ST`; Z−U → `-*-P/QR+STU`.

#### Method 2: the algorithm (2024 B Q3a: "show every push and pop")

1. **Reverse** the string.
2. **Swap** every `(` with `)`.
3. Run the postfix algorithm with ONE change: on **equal** precedence, pop **only** `^`.
4. **Reverse** the output.

| Stage | String |
|---|---|
| original | `(P-Q/R)*(S+T)-U` |
| 1. reversed | `U-)T+S(*)R/Q-P(` |
| 2. brackets swapped | `U-(T+S)*(R/Q-P)` |
| 3. modified pass output | `UTS+RQ/P-*-` |
| 4. reversed = prefix | **`-*-P/QR+STU`** |

::: tip Why the rule flips
Reversing the string also reverses associativity. With the normal postfix rule, `a-b-c` would come out as `-a-bc`, which means a−(b−c). That is wrong; the right answer is `--abc`. And `a^b^c` (right-associative) must give `^a^bc`, which is exactly what popping equal `^` on the reversed string produces.
:::

### 4. Postfix → Infix {#postfix-infix}

1. Scan left → right with a stack of strings.
2. Operand: push it.
3. Operator: pop **b** (right), pop **a** (left), push `(a op b)`.

Worked example: `PQ+RS*-T/`

| Symbol | Action | Stack (bottom → top) |
|---|---|---|
| P, Q | push | P · Q |
| + | pop b=Q, a=P → `(P+Q)` | (P+Q) |
| R, S | push | (P+Q) · R · S |
| * | pop b=S, a=R → `(R*S)` | (P+Q) · (R*S) |
| - | pop b=(R*S), a=(P+Q) | ((P+Q)−(R*S)) |
| T | push | ((P+Q)−(R*S)) · T |
| / | pop b=T, a=… | (((P+Q)−(R*S))/T) |

Result: `(((P+Q)-(R*S))/T)`, i.e. `(P+Q-R*S)/T`.

::: danger Dropping brackets safely
Remove a bracket pair only if the meaning stays the same. `A-(B-C)` and `A/(B*C)` must keep their brackets: the right operand of `-` or `/` changes meaning without them. In an MCQ, the option with the fewest brackets that still means the same thing is the intended one.
:::

**Practice:** 1. `ABC^D/-EF*+`

### 5. Prefix → Infix {#prefix-infix}

1. Scan **right → left**.
2. Operand: push it.
3. Operator: pop **a** (the left operand, popped first), pop b, push `(a op b)`.

Worked example: `/-P*QRS`: push S, R, Q → `*` gives `(Q*R)` → push P → `-` gives `(P-(Q*R))` → `/` gives `((P-(Q*R))/S)`, i.e. `(P-Q*R)/S`.

::: danger The classic slip
Using the postfix pop order here swaps every pair: `/-P*QRS` would come out as `S/(R*Q-P)`. Quick check: the operands must come out in the same order as in the prefix, P, Q, R, S.
:::

**Practice:** 1. `+*A-BC/DE`

### 6. Postfix → Prefix {#postfix-prefix}

Scan left → right; operand: push; operator: pop b, pop a, push `op a b`.

`PQR/-ST*+` → R/… gives `/QR` → `-P/QR` → `*ST` → **`+-P/QR*ST`**. Check through infix: `((P-(Q/R))+(S*T))`. When in doubt, go postfix → infix → prefix; the direct method only saves writing brackets.

**Practice:** 1. `AB+CD-*E^`

### 7. Prefix → Postfix {#prefix-postfix}

Scan right → left; operand: push; operator: pop a (first), pop b, push `a b op`.

`+-P*QR/S-TU` → `TU-` → `STU-/` → `QR*` → `PQR*-` → **`PQR*-STU-/+`**. Infix: `P-Q*R+S/(T-U)`.

**Practice:** 1. `*^A+BC-D/EF`

### 8. Evaluating postfix and prefix {#evaluation}

| | Postfix | Prefix |
|---|---|---|
| Scan | left → right | right → left (reverse the **tokens**, not the characters) |
| Operand | push | push |
| Operator | op2 = pop (1st), op1 = pop (2nd), push op1 op op2 | op1 = pop (1st), op2 = pop (2nd), push op1 op op2 |
| Answer | the single value left | the single value left |

Postfix `50, 6, 3, *, -, 2, 3, ^, 4, /, +` = **34**:

| Token | Action | Stack (bottom → top) |
|---|---|---|
| 50, 6, 3 | push | 50 6 3 |
| * | op2 = 3, op1 = 6 → 18 | 50 18 |
| - | op2 = 18, op1 = 50 → 32 | 32 |
| 2, 3 | push | 32 2 3 |
| ^ | op2 = 3, op1 = 2 → 8 | 32 8 |
| 4 | push | 32 8 4 |
| / | op2 = 4, op1 = 8 → 2 | 32 2 |
| + | op2 = 2, op1 = 32 → 34 | 34 |

Prefix `+, *, 2, -, 9, 4, /, 12, 3` = **14**: from the right, push 3, 12 → `/`: op1 = 12 (first pop), op2 = 3 → 4 → push 4, 9 → `-`: 9 − 4 = 5 → push 2 → `*`: 2 × 5 = 10 → `+`: 10 + 4 = 14.

::: danger What a pop-order mistake produces
MCQs include the wrong values: swapping the pop order turns 34 into −32 and 14 into −10. Write `op2 = pop, op1 = pop` at the top of your working so you cannot swap them.
:::

::: danger Four traps in evaluation questions
- Commas or spaces separate tokens: `12` is one number. In prefix, reverse the list of **tokens**; reversing characters turns 12 into 21.
- Integer division truncates toward zero in C++: `7/2 = 3`, `-3/2 = -1`.
- `^` is power here, not XOR.
- Only `-`, `/` and `^` care about order. That is exactly why examiners put them in.
:::

::: info Quiz favourite: the deepest the stack gets
Theory Quiz 2 (2026) Q9: `5 3 2 * + 8 4 / - 2 3 ^ *` gives **72**, and the stack is deepest (3) when three operands sit waiting: `5 3 2`, then `11 8 4`, then `9 2 3`. Count the stack column of your trace; do not guess from the length.
:::

### 9. MCQ speed tricks {#mcq-tricks}

**Trick 1: find the main operator.** The operator applied last is the last symbol of postfix and the first of prefix. In infix, look outside every bracket for the lowest precedence; on a tie of left-associative operators take the rightmost; in a chain of `^` take the leftmost.

| Infix | Main operator | Postfix ends with / prefix starts with |
|---|---|---|
| `(P-Q/R)*(S+T)-U` | the `-` outside the brackets | `…-` / `-…` |
| `P+Q*(R-S)^T/U` | `+` | `…+` / `+…` |
| `A^B^C` | the first `^` | `ABC^^` / `^A^BC` |

**Trick 2: the validity counter.** Walk left to right: operand +1, binary operator −1. The count must never drop below 1 after an operator and must end at exactly 1. `PQR/-ST*+`: 1, 2, 3, 2, 1, 2, 3, 2, 1, valid. `PQ+-R`: 1, 2, 1, 0, invalid.

**Trick 3: eliminate first.** *Postfix of `(P-Q/R)*(S+T)-U`?* (b) `PQ-R/ST+*U-` means (P−Q)/R, wrong; (c) `PQR/-ST+U-*` ends with `*`, but the main operator is `-`; (d) `QR/P-…` has Q before P. Only (a) `PQR/-ST+*U-` survives.

::: tip Where the three forms come from
Draw the expression as a tree: operators are internal nodes, operands are leaves. **Infix = inorder, prefix = preorder, postfix = postorder.** That is why the leaves (operands) keep their order in all three. Unit 5 uses this.
:::

::: danger Blank-level traps
- push is `arr[++top]` (pre-increment), pop is `arr[top--]` (post-decrement). `arr[top++]` writes to `arr[-1]` on the first push.
- In the linked push, **link first, then move**: `n->next = top; top = n;`. Swap the lines and the rest of the stack is lost.
- `int v = t->data;` is read **before** `delete t`. And `v` is an `int`, so the blank ends in `->data`.
- The top must be the **head**. If it were the tail, pop would need the node before it: O(n).
:::

::: info Memory: array stack vs linked stack (Theory Quiz 2, 2026, Q4)
A stack of capacity 200 as an array of 2-byte ints plus a 2-byte `top` costs 200 × 2 + 2 = **402 bytes**, however many elements it holds. As a linked list with 2-byte data, 4-byte pointers and a 4-byte `head`, n elements cost 6n + 4. The list costs strictly more when 6n + 4 > 402, so n > 66.3, and the smallest such n is **67**. The recipe for every question like this is in [Unit 1](./unit-1#memory).
:::

### 13. Valid pop sequences (stack permutations) {#pop-sequences}

1, 2, …, n are pushed in order and pops can happen at any time. Which outputs are possible?

::: tip The rule
An output is impossible exactly when it contains the pattern **big … small … middle** (c … a … b with a &lt; b &lt; c). Put another way: once you pop some x, every smaller element still waiting must come out in **decreasing** order.
:::

**The simulation method** (bulletproof): for each number in the output, push until it is on top, then pop it. If the number you need is already inside the stack but not on top, the sequence is impossible.

| insertAtBottom | empty → push x | recurse, then push t back | O(n) / O(n) |
| reverseStack | empty → return | reverse the rest, then insertAtBottom(t) | **O(n²)** / O(n) |
| sortedInsert | empty or top ≤ x → push x | recurse, then push t back | O(n) / O(n) |
| sortStack | empty → return | sort the rest, then sortedInsert(t) | O(n²) / O(n) |
| deleteMiddle | k == 0 → pop (that's the middle) | recurse with k−1, then push t back | O(n) / O(n) |

::: danger Order-of-lines trap
In reverseStack, if `insertAtBottom(s, t)` runs before `reverseStack(s)`, the stack is back to full size when the recursive call happens. It never shrinks, the recursion never ends, and the program crashes with a stack overflow. The recursive call on the **smaller** stack must come first. This is also why 2024 B Q4(a), "reverse a stack using recursion", is **O(n²)** in the worst case.
:::

## Traps and the 5-minute checklist {#traps}

| # | Trap | Correct version |
|---|---|---|
| 1 | `int x = s.pop();` with `std::stack` | compile error: STL `pop()` returns void. `top()` first, then `pop()` |
| 2 | pop order in evaluation | postfix: 1st pop = right. Prefix (scanned backwards): 1st pop = left |
| 3 | `^` treated as left-associative | `a^b^c = a^(b^c)` → postfix `abc^^`; the second `^` is pushed, not popped |
| 4 | `arr[top++]` in push, `arr[--top]` in pop | `arr[++top]` and `arr[top--]` |
| 5 | a blank of the wrong type | `Node*` ↔ `Node*`, `int` ↔ `->data`, index ↔ `arr[index]` |
| 6 | "no extra stack, so O(1) space" | recursion depth n is O(n) space |
| 7 | a bracket checker missing one of the 3 checks | unmatched closer, leftover opener, wrong type |
| 8 | `<` instead of `<=` in min-stack or next greater | duplicates break both |
| 9 | swapping the lines in reverseStack | infinite recursion, stack overflow |
| 10 | reversing characters of a multi-digit prefix | reverse the tokens: 12 stays 12 |
| 11 | integer division in evaluation | `7/2 = 3`, `-3/2 = -1` (toward zero) |
| 12 | "a loop inside a loop is O(n²)" | count total pops: the monotonic stack is O(n) |

**The checklist:**
1. For every blank: what type is it? Pointer, index, or value.
2. For every function: what happens when it is empty, has one element, is full?
3. Recursion: where is the print relative to the call? What is the base case? Does the call run on a smaller input?
4. Conversions: find the main operator first. Check the operand order and the first and last symbols. Then convert.
5. Evaluation: write `op2 = pop, op1 = pop` at the top of your working.

What is the postfix form of `A ^ B ^ C * D`?

<Mcq :options="['AB^C^D*', 'ABC^^D*', 'ABCD*^^', 'AB^CD*^']" answer="b">

`^` is right-associative, so `A^B^C = A^(B^C)` → `ABC^^`, then `* D` → `ABC^^D*`. The trap (a) treats `^` as left-associative, the single most common conversion error.

</Mcq>

<Drill n="2" tag="Evaluation">

Evaluate the postfix `100, 8, 2, /, 5, *, -, 3, 4, ^, +`.

<Mcq :options="['161', '-36', '81', '179']" answer="a">

8/2 = 4, × 5 = 20, 100 − 20 = 80, 3⁴ = 81, 80 + 81 = **161**. −36 is what swapping the pop order everywhere gives.

</Mcq>

<FillIn q="Convert infix to prefix: `(A + B) * C - D / E`. Type it with no spaces." answer="-*+ABC/DE">

<Drill n="4" tag="Conversion">

Which infix expression does the prefix `- + A * B C D` represent?

<Mcq :options="['(A+B*C)-D', 'A+B*(C-D)', '((A+B)*C)-D', 'A-(B*C+D)']" answer="a">

Scan right to left: `*` → `(B*C)`; `+` → first pop A (left), then (B*C): `(A+B*C)`; `-` → first pop (A+B*C), then D: `(A+B*C)-D`.

</Mcq>

<Drill n="5" tag="Stack">

1, 2, 3, 4, 5 are pushed in that order, with pops allowed at any time. Which output is impossible?

<Mcq :options="['3 2 1 5 4', '2 4 3 1 5', '4 2 3 1 5', '1 2 3 4 5']" answer="c">

After 4 is popped, 1 2 3 wait with 3 on top, so 2 cannot come next. (b) works: push 1 2, pop 2, push 3 4, pop 4 3 1, push 5, pop 5.

</Mcq>

<Drill n="6" tag="Code">

What is the outcome? `stack<int> s; s.push(5); s.push(7); int x = s.pop(); cout << x;`

`std::stack::pop()` returns `void`, so `int x = s.pop();` does not compile ("void value not ignored as it ought to be"). Use `int x = s.top(); s.pop();`.

A stack of n elements is reversed recursively using insertAtBottom (no extra stack, no array). Time and space?
